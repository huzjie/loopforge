# ADR-0005：四层记忆 + L0 不可压缩层

- 状态：已接受
- 日期：2026-08-03
- 关联：PRD 设计难点二「上下文治理的信息保真度」；ARCHITECTURE §8.2

## 背景

长程自主编程（16 天、265 commits）要求 Agent 在数千轮循环后仍然
记得第 1 天定下的架构约束。主流做法（截断旧消息）会丢失约束；
全量保留会撑爆上下文窗口。

## 决策

采用**五层记忆模型**：

| 层 | 内容 | 压缩策略 |
|---|---|---|
| L0 Pinned | 不可压缩约束 | 永不压缩、永不裁剪（硬配额 8%） |
| L1 Working | 当前循环即时上下文 | 仅结构化裁剪 |
| L2 Episodic | Run 级历史事件 | 三级压缩 |
| L3 Semantic | 代码库知识/跨 Run 经验 | 重建而非丢弃 |
| L4 Milestone | 递归摘要树 | 更高层摘要 |

三条不可动摇的保障：

1. **原文永不物理删除** —— 压缩只写 `compressed_into` 标记；
2. **压缩谱系** —— `memory_lineage` 记录每个摘要的来源与信息损失；
3. **保真度校验** —— 每轮 `check_fidelity` 核对 Pinned 约束的关键事实。

## 替代方案

- **截断窗口**：实现简单，但约束必丢，被否决（直接违反 PRD 难点二）。
- **全量保留 + 大窗口**：token 成本随轮次线性增长，不可持续。

## 后果

- 正向：第 300 轮与第 20 轮的约束等价；审计可回溯任意摘要到原文。
- 负向：实现复杂度高于截断；`check_fidelity` 需要可验证的文本核对。
- 缓解：L1/L2 压缩纯规则（确定性、零成本），L3 才允许 LLM。
